Platform & Use-Case Overview

APIX is the proof. The LLMOps platform is the product.

A reusable foundation for building, evaluating and operating AI use cases — explained end to end, using APIX (AFNI Performance Index), AFNI's call-analytics pipeline, as the working example. Written to be followed by someone seeing this for the first time.

Subject LLMOps platform · APIX pipeline Audience Program & business stakeholders Read time ~10 minutes

New here? Start with this

APIX listens to every customer call, judges how the agent handled it, and turns that into a weekly coaching scorecard. The platform is the shared machinery that runs it safely and lets us improve it. This document explains both — the machinery first, then APIX as the example — with a worked example in each section.

01 · The big picture

One reusable platform, many use cases

The work is not a single call-analytics application. It is a standardized LLMOps platform — a common foundation for deploying and operating any number of AI use cases. APIX, AFNI's contact-centre performance pipeline, is simply the first use case that runs on it and proves it works.

Every use case reuses the whole platform and supplies only its own recipe: its data, its prompts, and how it wants to be measured. Nothing underneath has to be rebuilt.

  • The platform gives every use case: prompt & model management, evaluation, monitoring, guardrails, feedback and controls.
  • A use case adds only its evaluation schema, prompts, KPI definitions and its golden data.
  • Future use cases already in view — hiring intelligence, agent knowledge-assist, automated quality-scoring, coaching-plan generation — inherit all of it.
Analogy

Think of a car factory

The factory — the robots, the assembly line, the quality checks — is the platform. It doesn't change from car to car.

Each car model is a use case. It reuses the entire factory and only brings its own blueprint and parts.

→ APIX is the first car off this line. The value we're building is the line, not just the car.

02 · The platform, capability by capability

What every use case gets for free

Seven capabilities make up the platform. All seven are already connected to APIX through a single connection point, so the pipeline benefits from them today without carrying their complexity in its own code. Each below has a one-line example of what it does in practice.

1

Prompt Management

Prompts live in a versioned library, separate from code. Approved changes go live without a software release.

Example: a prompt engineer improves the wording that detects escalations and publishes “v4” — no developer needed.
2

Model Management

Code refers to a model by a nickname; a registry maps it to the real model, per environment.

Example: switch from one model to a newer one for everyone by changing one setting, not the code.
3

Evaluation Gate

Before a change ships, it is scored against a trusted test set; weak changes are blocked.

Example: a new prompt scores 82% vs the required 90% → automatically rejected before customers see it.
4

Monitoring

Every model call is tracked — cost, speed, errors — so runs can be watched and costed.

Example: spot that one step's cost doubled overnight and act on it the same day.
5

Guardrails & Audit

Checks such as personal-data detection run on the way through; flagged events are kept for review.

Example: a customer's card number in a transcript is detected and logged, not passed on blindly.
6

Feedback Loop

Users rate a result and comment; that feedback drives prompt and test-set improvements.

Example: a coach marks a coaching tip 2/5 → the case is reviewed and the prompt fixed.
7

Operational Controls

Rate-limits, retries and a safe test mode keep large runs reliable and within provider limits.

Example: scoring 100,000 calls without tripping the AI provider's rate limits.
03 · How APIX works

From a raw call to per-agent coaching, in five steps

APIX runs weekly. It takes raw call transcripts and turns them into a coaching scorecard for every agent. Each step feeds the next; the AI is used where judgment is needed, and plain calculation everywhere else.

STEP 1

Denoise

Cleans messy speech-to-text so later steps judge content, not typos.

raw → clean
STEP 2

Analysis

Scores every call against the program's checklist — with the evidence behind each point.

call → evaluation
STEP 3

Summary

Rolls a week of a coach's calls into per-agent scores and a coaching note.

week → scorecard
STEP 4

Individual metrics

Adds operational numbers from Verizon and writes tailored tips.

+ AHT / VXS
STEP 5

KPI aggregator

Flattens everything into the weekly file the dashboard reads.

→ dashboard

A defining strength: every judgment is backed by evidence — the exact call moments that support it are recorded with the result. Coaching is auditable, not a black-box score.

Three programs, three lenses

The same pipeline serves three Verizon lines of business; each has its own checklist because “a good call” means something different in each.

  • Telesales — a sales lens (pitches, upgrades, saves). 12 KPIs.
  • WCC — care & retention across LEARN / PROVIDE / CLOSE. 11 KPIs.
  • PSO — VZ Mobile care, the most detailed. 24 KPIs.
Worked example · follow one call

A single sales call through APIX

Customer asks about their bill. Agent resolves it, then offers a second line. Customer declines. ↓ Step 2 (Analysis) judges: new_line_opportunity_exists = true pitched_new_line = true issue_resolved = true customer_experience = "Good" ↓ Step 3 counts it toward: this agent's new-line pitches +1

Every one of those judgments links back to the exact sentence in the call that justifies it.

04 · The metric system

How one call becomes measurable KPIs

This is the heart of APIX. There are four kinds of metric, produced in a clear chain: the AI judges each call; those judgments are added up per agent into KPIs; operational numbers from Verizon are joined in; and a few roll-up scores summarize the week.

A prompt only ever changes the first link. Everything after it is arithmetic — which is what makes the system testable.

  • KPIs — counts and rates of behaviours and outcomes (e.g. how many pitches, what share resolved).
  • Behaviour & soft-skill scores — how consistently a skill shows, as a 0–1 average.
  • Operational metrics — handling time, VXS, resolution — from Verizon's data, not the AI.
  • Roll-up scores — a composite score and status that summarize the week for managers.
Worked example · a KPI calculation

“New-line pitches” for one agent

In the week, this agent had: 20 calls where a new-line opportunity existed 12 of those, they pitched → new_line_pitches = 12 → opportunity_missed = 8 / 20 = 40%

No labelling needed here — it is pure counting on top of the call-level judgments.

05 · Evaluation & golden data

How we prove the system is right — and keep it right

To improve prompts safely we need “ground truth”: examples where the correct answer is agreed. The challenge is that APIX KPIs are aggregated across many calls, so a naïve “one transcript → one KPI value” can't validate them. The resolution: a prompt change can only affect one part, so we evaluate each part the right way.

L1
Call-level analysis
The per-call judgments the AI makes
Golden set — coaches certify
L2
Aggregation into KPIs
Counts and rates — plain arithmetic
Automated tests
L3
Coaching narrative
The weekly written recommendations
SME rubric
SQL
Operational metrics
AHT, VXS — from Verizon's warehouse
Validate the query
Certify the call-level judgments and test the arithmetic, and every aggregate KPI is right by construction. AHT / VXS / resolution rate aren't AI outputs at all — golden data doesn't apply to them.
Worked example · one golden record

What a coach certifies

Transcript #4471 (Telesales) Coaches agree the correct answer is: new_line_opportunity_exists = true pitched_new_line = false escalation = none customer_experience = "Medium" Evidence: lines 12–14 of the call Certified by: 2 coaches · 8 Sep

A transcript becomes “golden” only when ≥2 coaches agree on its answers — not because we picked it.

What makes a transcript “golden”

Deliberate coverage, not random selection: the set must include calls that exercise each decision (each opportunity type, each experience rating, escalations vs none, edge cases), with enough positive and negative examples, kept only where reviewers agree. If two coaches disagree, that tells us the definition needs fixing — before the record can be golden.

08 · Glossary

Terms used in this document

APIX
AFNI Performance Index — the call-analytics pipeline; the first use case on the platform.
LLMOps platform
The reusable foundation for building and operating AI use cases — the “factory.”
Use case
One application on the platform, supplying its own schema, prompts, KPIs and data.
KPI
A key performance indicator — a count or rate derived from the per-call judgments.
Schema
The fixed checklist of fields the AI fills in for each call.
Golden dataset
Curated calls with business-certified correct answers, used to evaluate changes.
Evaluation gate
The check that scores a change against the golden set before it ships.
Evidence
The exact call moments recorded behind each judgment — the audit trail.
AHT / VXS / FCR
Operational metrics: average handling time, Verizon experience score, first-contact resolution.
SME
Subject-matter expert — here, coaches and the internal APIX specialists.
