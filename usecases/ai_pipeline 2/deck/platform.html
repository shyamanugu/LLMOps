Why it's reusable — three design rules

1 · Onboard by config

A new use case is a handful of YAML entries — model aliases, a guardrail policy, prompts, eval thresholds — not new code.

2 · Safe by default

Every component ships a no-op default (null tracer, pass-through guardrail, in-memory store), so a use case can adopt one piece at a time and run before any cloud resource exists.

3 · Composable

Components are independent and injected explicitly. Take only what you need; the rest stays dormant.

The bottom line

10 of the 14 components are fully reusable as-is across any GenAI use case; the remaining four are reusable patterns/policies. This is what makes the 2nd, 5th, and 20th use case cheap.
