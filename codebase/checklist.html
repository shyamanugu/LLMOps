LLMOps Platform — Manual Setup Checklist

Everything you create by hand to stand up the framework in the client Azure + GitHub environment. Check items off — your progress is saved in this browser. Code placeholders to finish are in todo.html.

0%
Before you start: you need an Azure subscription with permission to create resources and assign roles, and a GitHub repository with permission to configure Environments and OIDC. Prefer Managed Identity over keys everywhere. Region: pick one with your required Azure OpenAI models available.

1 · Azure foundation resource group & identity

  • Create a resource group per environment (e.g. rg-llmops-dev, -test, -prod).Keeps environments isolated; matches the dev/test/prod promotion model.
  • Create a user-assigned Managed Identity (or use the Container App system identity).The app authenticates to Azure OpenAI, Search, Cosmos, Key Vault with this — no keys in code.
  • Create a Log Analytics workspace.Backing store for Application Insights + Container Apps logs.

2 · Azure OpenAI & model deployments the models

  • Create an Azure OpenAI resource. Note the endpoint.Set as LLMOPS_AZURE_OPENAI_ENDPOINT.
  • Deploy the models and record the deployment names: a reasoning model, a small/cheap model, a realtime voice model, and an embedding model.Put the deployment names into platform/models.yaml (aliases reason / bulk / judge / voice / embed).
  • Confirm quota / rate limits (tokens per minute) are enough, or request an increase.Quota approval can take time — do it early.
  • Assign the identity the Cognitive Services OpenAI User role on the resource.

3 · Supporting Azure services

  • Azure AI Search (RAG index). Create a service (Basic ≈ $74/mo or Standard). Assign Search Index Data Contributor/Reader.LLMOPS_AZURE_SEARCH_ENDPOINT. Backs search_knowledge.
  • Azure AI Document Intelligence (file extraction).LLMOPS_DOCUMENT_INTELLIGENCE_ENDPOINT. Backs extract_document.
  • Azure AI Content Safety (guardrails).LLMOPS_CONTENT_SAFETY_ENDPOINT. Backs the guardrail engine (Prompt Shields, categories).
  • Azure Cosmos DB (agent state + feedback). Create a database llmops.LLMOPS_COSMOS_ENDPOINT. Assign the data-plane role to the identity.
  • Azure Storage account (transcripts, golden datasets, blobs).
  • Azure Key Vault — store any secrets (Search key if used, Langfuse keys). Assign Key Vault Secrets User.
  • Application Insights (linked to the Log Analytics workspace).LLMOPS_APPLICATIONINSIGHTS_CONNECTION_STRING. System of record for traces + cost.

4 · Compute, gateway & registry

  • Azure Container Registry (ACR).CI pushes backend + frontend images here.
  • Azure Container Apps environment (per environment).Hosts the backend API and the frontend. Deploy via infra/ Bicep or the deploy workflow.
  • Azure API Management (the gateway).Apply the policies in platform/gateway/apim-policies/ (rate limit, quota, JWT validation).

5 · Langfuse (self-hosted observability + prompt registry)

  • Deploy Langfuse as a Container App + Azure Database for PostgreSQL (Bicep module langfuse.bicep), or run locally via infra/docker-compose.yml for dev.MIT-licensed, ~$50–150/mo infra. Keeps LLM data in your network.
  • Create a Langfuse project and copy the public + secret keys.LLMOPS_LANGFUSE_HOST/PUBLIC_KEY/SECRET_KEY.

6 · GitHub setup

  • Create the repository and push this codebase/ content.
  • Create an Entra ID app registration for GitHub OIDC and add a federated identity credential for the repo/environments.Lets Actions log in to Azure with no stored secret.
  • Add repo variables: AZ_CLIENT_ID, AZ_TENANT_ID, AZ_SUB_ID, ACR name, resource-group names.
  • Create GitHub Environments dev, test, prod and set required reviewers on test + prod.This is the promotion gate.
  • Assign the OIDC identity Contributor (or scoped roles) on the resource groups.
  • Confirm branch protection requires pr-checks (the evaluation gate) to pass before merge.

7 · Configuration files to fill

  • Set the deployment names in platform/models.yaml to match your Azure OpenAI deployments.
  • Copy backend/.env.example → backend/.env and fill endpoints (dev only).
  • Set frontend/.env → VITE_API_BASE to the backend URL.
  • Fill each use case's usecases/<name>/config/datasources.yaml (search index names, DB tables, systems).
  • Review platform/evaluators/defaults.yaml thresholds; adjust per use case in usecases/<name>/evals/evaluators.yaml.
  • Finish the code placeholders in todo.html (the # TODO(wiring) markers).

8 · Golden datasets (with the SMEs)

  • Author the first golden dataset per use case (and per program for APIX: Telesales + WCC), ~50–200 cases, in usecases/<name>/evals/golden.*.jsonl.This is the evaluation gate. Start SME-authored; grow from real traffic later.
  • Set thresholds in the use case's evaluators.yaml from a baseline run.

9 · First run & deploy

  • Local dev: docker compose -f infra/docker-compose.yml up (backend + frontend + Langfuse + Postgres).
  • Run the backend tests: cd backend && make test.
  • Run the evaluation gate locally: python backend/evals/run.py --usecase apix --subset all.
  • Provision infra: deploy infra/main.bicep (or let the deploy workflow do it).
  • First deploy: merge to main → the deploy workflow builds, gates, and promotes dev → test → prod (canary).
  • Open the Console and confirm Dashboard, Traces, Costs, Evaluations render.
Then onboard a use case: run the prompts in copilot_prompts.py (the USE_CASE_PROMPTS section) via GitHub Copilot to generate usecases/apix and usecases/hiring content. The framework is already done.
